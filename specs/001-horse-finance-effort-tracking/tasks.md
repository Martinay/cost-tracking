## Format and path conventions

- Tasks use `- [ ] Tnnn [P?] [USn?] Description with exact file paths`.
- Paths are relative to repository root.
- `[P]` identifies tasks that may run together only at the prerequisite boundary stated below; it never overrides a phase barrier or test-before-code order.
- Backend: `backend/src/CostTracking.Api/` and `backend/tests/CostTracking.Tests/`; frontend: `frontend/src/` and `frontend/tests/`; deployment: `infra/`; executable validation: `scripts/`.
- The coordinator owns shared files (`Program.cs`, generated OpenAPI/types, route registration, manifests, and this task list). Serialize changes to these files. GPT Luna subagents can own bounded `[P]` test/component tasks with disjoint files; they must receive applicable contracts and prerequisite task IDs. Do not delegate an entire storage/authentication subsystem as a small task.
- For each new event variant, add schema-valid positive/negative fixtures and replay assertions in the same slice. Generated client types come from the typed API; no handwritten browser money, schedule, or reporting engine.
- All user-facing slices require a running-interface check against `contracts/ui.md`; retain drafts on recoverable errors, use accessible labels/status/focus, and acknowledge success only after server confirmation.

## Implementation Strategy

### MVP first

Complete Setup, Foundation, and US1 (T001–T045). Demonstrate sign-in → settings → horses → exact one-time ledger → monthly/lifetime balance/history, including a second-owner isolation attempt, restart, and recoverable failure. This is the smallest useful product. A locally working MVP does not waive external authentication/storage/security release gates.

### Incremental delivery

Add US2's virtual recurring expenses, then US3's explicit income decisions. Add US4 as two smaller slices (driving, then activity), then US5's comparison views. At each checkpoint regenerate contracts, run the related regression suite, and verify the real interface. Use exact existing contract constraints rather than inventing missing policy while coding; unresolved contradictions must be resolved in the canonical design before implementation.

### Release and unavailable resources

T102–T106 require staging credentials/domains, real synthetic Azure resources and independent backup storage, measurement runs, human participants, and billing evidence. Prepare reviewable code/scripts first; keep the execution task unchecked and report the specific missing resource if unavailable. Do not provision paid infrastructure or conduct destructive fault tests against real user data as an incidental implementation step. A failed integrity/privacy/durability proof blocks release. A failed budget target requires a revised deployment choice or explicit budget exception. No exports, sharing, payment integration, tax accounting, correction workflow, scheduler, or extra data store is added.
