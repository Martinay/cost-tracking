# User Story 1: Private horse ledger

**Local acceptance: verified.** The isolated HTTP-backed browser journey signs in through the TestHost fixture, prepares an account and horse, records an expense, and reconciles the ledger with monthly P&L, expense category, income source, activity, and complete lifetime reports. The final browser suite passed 21/21; the private-ledger journey uses the real local API and event store. See [frontend-journeys.md](frontend-journeys.md) and [backend-acceptance.md](backend-acceptance.md#frontend-owned-story-acceptance).

The exact split example is €10.01 across two horses: €5.01 (501 minor units) and €5.00 (500 minor units). This follows the canonical allocation contract and the one-time ledger integration coverage. Confirmation is based on the committed response; the client retains the draft and key on recoverable failures. The browser suite checks onboarding and keyboard entry, and its owner-isolation journey confirms a second fixture identity cannot read the first owner's horse.

The separate TestHost restart regression was observed as HTTP 503 (`stream_unreadable`) after deterministic event IDs repeated across host instances. Sharing the fixture GUID source fixed it; the focused regression and final 21/21 browser run passed, including persisted account behavior across restart. This is test-host restart evidence, not an Azure Files or WorkOS staging proof. The detailed red-first gaps for T041 remain open; later green tests do not establish an earlier red. Actual hosted sign-in and target-storage recovery remain external gates.
