# Research

## Decisions
- Use explicit shortcut selection plus Save task. Rationale: two predictable actions prevent accidental activity records. Considered immediate-save buttons; rejected because horse/date/minutes need review.
- Store account-scoped browser preferences and disclose no device sync. Rationale: smallest useful slice with no new event variants; permanent logs still use server acknowledgment. Considered server-synced templates; requires a separate event lifecycle beyond this slice.
- Keep predefined reporting types and put custom names in notes. Rationale: existing schema and historical replay remain compatible. Considered unrestricted task-type strings; would disrupt reporting contracts.
- Use the existing Modal, native selects and CSS tokens. Rationale: accessible focus lifecycle and no dependencies.
All technical questions resolved from repository source; no external research required.
